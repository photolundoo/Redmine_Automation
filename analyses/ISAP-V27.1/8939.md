## 1. Étude du sujet

Le ticket signale que Tomcat n'était plus accessible en mode non-HTTPS avec le fichier de configuration fourni ; l'ancien fichier de 2024 contournait le problème. La résolution identifie trois réglages : `transport-guarantee` était réglé à `CONFIDENTIAL` au lieu de `NONE`, le commentaire « Enable HSTS » était devenu « HTTP header security », et le paramètre correspondant était activé au lieu d'être désactivé. Le ticket est résolu le 16/10/2026.

## 2. Compte rendu de la situation

**Tenants.** Une configuration incorrecte peut imposer un accès HTTPS même lorsqu'un connecteur HTTP non-HTTPS est configuré. Les paramètres HSTS et de garantie de transport doivent être cohérents avec le protocole utilisé.

**Aboutissants.** Le ticket a corrigé les valeurs de configuration fautives. Le plan d'installation contient déjà des vérifications HTTP et HTTPS, qui peuvent couvrir le retour au comportement attendu.

**Objectifs du test.** Vérifier l'accès à IsapReporting avec HTTP lorsque TLS est désactivé et avec HTTPS lorsque TLS est activé, en contrôlant les valeurs corrigées de transport-guarantee et HSTS.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** La recherche de `#8939` dans les plans ne retourne aucune étape. La fiche INS04 « Installation complète d’un serveur-client » du plan 11 comporte une section Configuration du Serveur part 2 : elle demande d'activer TLS pour les adresses HTTPS et de désactiver l'option pour les adresses non-HTTPS, puis de tester différents ports et connexions à IsapReporting. La fiche ne contrôle pas les valeurs de `transport-guarantee` ni le réglage HSTS à l'origine du défaut.

**Comparaison des procédures.** INS04 couvre déjà la configuration des deux protocoles et la connexion à IsapReporting ; conserver ces étapes et ajouter la vérification des réglages corrigés évite de créer une procédure dupliquée.

**Issue retenue.** Issue B — Adapter l'existant : compléter INS04 par les contrôles de `transport-guarantee` et HSTS avant les essais d'accès non-HTTPS et HTTPS.

## 4. Procédure de test proposée

**Écarts avec la procédure existante.** Conserver les étapes INS04 qui testent les connecteurs HTTP et HTTPS avec TLS activé ou désactivé. Ajouter le contrôle des trois valeurs corrigées, puis vérifier que chaque protocole aboutit au comportement prévu.

**Accès à IsapReporting sans HTTPS**
- Sur le clone de test, désactiver TLS dans la configuration Tomcat et appliquer la configuration du serveur. Résultat attendu : le connecteur HTTP est actif et la configuration n'impose pas de transport confidentiel. (#8939)
- Vérifier dans la configuration déployée que `transport-guarantee` vaut `NONE` et que le paramètre HSTS est désactivé. Résultat attendu : le mode HTTP n'est pas redirigé ni bloqué par une exigence HTTPS ou par HSTS. (#8939)
- Depuis un navigateur de test, ouvrir IsapReporting via l'URL HTTP et le port configuré. Résultat attendu : la page se charge en HTTP et l'utilisateur peut accéder à l'écran de connexion. (#8939)
- Se connecter avec un compte de test sur le clone. Résultat attendu : l'authentification aboutit et la page protégée d'IsapReporting s'affiche sans redirection vers HTTPS ni erreur de transport. (#8939)
- Activer TLS selon la procédure INS04 et ouvrir IsapReporting via l'URL HTTPS correspondante. Résultat attendu : la page se charge en HTTPS et la configuration TLS n'est pas affectée par le réglage requis pour HTTP. (#8939)
- Consulter les journaux Tomcat et IsapReporting pour les deux protocoles. Résultat attendu : aucune erreur de contrainte de transport ni boucle de redirection n'est enregistrée. (#8939)

### Prérequis et moyens

- Environnement cloné et réinitialisable ; ne pas désactiver TLS sur un serveur client ou exposé.
- Utiliser des comptes de test et une URL interne isolée.
- Restaurer la configuration initiale après l'essai et ne pas conserver de mot de passe dans les résultats.

## 5. Intégration proposée

Dans le plan 11, compléter **INS04 — Installation complète d’un serveur-client**, section « Configuration du Serveur part 2 », par le contrôle de `transport-guarantee` et du paramètre HSTS, puis conserver les étapes existantes de test HTTP et HTTPS.
