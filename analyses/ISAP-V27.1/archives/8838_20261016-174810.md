## 1. Étude du sujet

Le ticket demande la création du moteur du dashboard et l'implémentation du comportement du tableau et de ses wrappers. L'historique énumère ensuite des fonctionnalités ajoutées : responsive des widgets, import/export, modification des noms, types de graphiques, sélection de période, verrouillage des widgets, dashboards imbriqués, widgets d'incidents et d'actions, règles et export PDF. Le ticket ne définit pas les résultats attendus ni les scénarios d'acceptation de ces comportements.

## 2. Compte rendu de la situation

**Tenants.** La Fonction est « WebApp - Statistiques », mais le sujet porte sur un dashboard à widgets, qui n'est pas nécessairement l'onglet Statistiques MC03. Le plan 14 contient un « Tableau de bord » de la planification, avec des données de ressources et des exports Excel ; ce périmètre est distinct.

**Aboutissants.** Le ticket est résolu à 100 % ; le commentaire final indique qu'une V2 du cas sera faite après retours utilisateurs. Les nombreux ajouts décrits dans l'historique n'établissent pas un jeu de données ni un résultat attendu pour chaque fonction.

**Objectifs du test.** Définir une procédure validée pour le dashboard WebApp avant de déclarer la fonctionnalité vérifiée. La documentation fonctionnelle mentionnée dans la correspondance n'a pas été consultée, conformément à l'interdiction de lire `.env`.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** `#8838` : aucune occurrence dans les plans. « dashboard » et « tableau de bord » : plan 01, fiche MC03 « Onglet Statistiques », qui couvre les statistiques et graphiques liés aux incidents ; aucune procédure de dashboard à widgets identifiée. Le plan 14, fiche MC08 « Onglet Planification », comporte un tableau de bord de planification portant sur les ressources, prestations, lieux, missions, et un export Excel ; il ne couvre pas le dashboard décrit par ce ticket.

**Issue retenue.** C — Créer une fiche dédiée au dashboard WebApp plutôt que de confondre ce nouveau module avec les statistiques MC03 ou le tableau de bord de planification MC08.

## 4. Procédure de test proposée

**Écarts avec la procédure existante.** Aucune fiche ne décrit le dashboard générique du ticket. Les scénarios ci-dessous sont une proposition de périmètre à faire relire ; les critères d'acceptation de chaque widget et de ses règles doivent être précisés avant exécution finale.

**Tableau de bord WebApp — proposition à faire valider**
- Ouvrir le dashboard de la version ISAP-V27.1. Résultat attendu : la page et le tableau de bord s'affichent sans erreur bloquante. (#8838)
- En mode édition, ajouter ou modifier un widget et changer son nom. Résultat attendu : le nom saisi est visible sur le widget après validation. (#8838)
- Modifier la taille d'affichage du navigateur. Résultat attendu : les widgets restent affichés dans la page sans chevauchement manifeste. (#8838)
- Utiliser les fonctions d'import et d'export disponibles dans le dashboard. Résultat attendu : l'import charge une configuration reconnue et l'export produit un fichier exploitable ; le format et le contenu attendus restent à préciser. (#8838)
