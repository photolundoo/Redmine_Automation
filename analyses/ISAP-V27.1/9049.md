## 1. Étude du sujet

Le dossier Fingerprints contient des fichiers de migration de base et ne doit pas être exécuté lors du remplissage initial. Le ticket indique que ServerConfiguration traitait auparavant les fichiers `.priv` présents dans ce dossier, ce qui créait des templates en doublon et des erreurs. Le correctif ignore les dossiers dont le nom contient `FingerPrints`.

## 2. Compte rendu de la situation

**Tenants.** Le dossier de migration peut contenir des fichiers `.priv` qui ne sont pas destinés à la configuration initiale d'une base vierge.

**Aboutissants.** Le ticket est résolu ; l'exclusion du dossier FingerPrints a été ajoutée au parcours de remplissage initial. Une note demande de s'assurer que le fichier de configuration de test conserve son extension `.isap`.

**Objectifs du test.** Vérifier que ServerConfiguration ignore le contenu du dossier Fingerprints lors du remplissage initial, évite la création de templates dupliqués et continue de traiter les fichiers `.isap` ordinaires nécessaires à la configuration.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** La recherche de `#9049`, « Fingerprints » et « .priv » dans le plan 11 ne retourne aucune étape. INS04 « Installation complète d’un serveur-client » contient une étape de réinitialisation de la base lors d'une première installation, mais ne contrôle pas l'exclusion des fichiers de migration. Le plan 12 couvre les migrations et les fingerprints lors d'une montée de version ; il ne teste pas leur exclusion du remplissage initial.

**Comparaison des procédures.** L'étape de première installation d'INS04 fournit le parcours adapté pour lancer ServerConfiguration et remplir une base neuve. Elle ne vérifie pas le contenu du dossier Fingerprints ni l'absence de doublons ; ces assertions complètent donc cette procédure sans remplacer les contrôles de configuration existants.

**Issue retenue.** Issue B — Adapter l'existant : INS04 couvre la première configuration serveur, mais pas l'exclusion spécifique des fichiers de migration Fingerprints.

## 4. Procédure de test proposée

**Écarts avec la procédure existante.** Conserver l'étape de première installation et de réinitialisation de la base dans INS04. Dans un clone, ajouter un fichier `.priv` de test dans Fingerprints et vérifier séparément le traitement des fichiers `.isap` ordinaires.

**Remplissage initial de la base**
- Restaurer un clone de test vierge avec un dossier nommé `FingerPrints` contenant un fichier `.priv` de test, et confirmer que le fichier de configuration attendu porte l'extension `.isap`. Résultat attendu : les fichiers de test sont présents avant le premier lancement sans modifier les sources partagées. (#9049)
- Lancer ServerConfiguration et effectuer le remplissage initial de la base. Résultat attendu : l'opération se termine sans erreur liée à des templates en double et le fichier `.priv` du dossier FingerPrints n'est pas exécuté. (#9049)
- Consulter les templates créés et comparer leur nombre et leurs noms aux données de référence avant lancement. Résultat attendu : aucun template provenant exclusivement du dossier FingerPrints n'est créé en doublon. (#9049)
- Vérifier le traitement des fichiers `.isap` de configuration initiale placés hors du dossier Fingerprints. Résultat attendu : les éléments requis de configuration sont créés normalement, sans que l'exclusion de Fingerprints ne bloque les autres fichiers. (#9049)
- Consulter les journaux de ServerConfiguration à la fin du remplissage initial. Résultat attendu : aucune erreur d'exécution d'un fichier `.priv` issu de Fingerprints n'est présente. (#9049)

### Prérequis et moyens

- Un clone de base réinitialisable et une copie de test des fichiers de configuration ; ne pas modifier les fichiers partagés du dépôt.
- Un fichier `.priv` de test et des fichiers `.isap` ordinaires dans les emplacements attendus.
- Un accès en lecture aux templates résultants et aux journaux de ServerConfiguration.

## 5. Intégration proposée

Dans le plan 11, compléter **INS04 — Installation complète d’un serveur-client** après l'étape « Si cas de première installation, réinitialiser la base de données », avec le contrôle d'exclusion du dossier Fingerprints et de maintien du traitement des fichiers `.isap` ordinaires.
