## 1. Étude du sujet

Le ticket porte sur l'installation et la configuration de SecurityCenter 5.14. Lors de la migration, Genetec n'a pas démarré correctement et les journaux ont montré une erreur SQL 242 : conversion d'une valeur `varchar` en `datetime` hors limites pendant l'initialisation de la base Directory. Le contournement utilisé a consisté à définir la langue par défaut du login SQL `sa` sur `us_english`. Le ticket est ensuite passé à l'état résolu ; il ne précise pas si cette configuration a été conservée comme prérequis permanent ni si la base a été restaurée après le test.

## 2. Compte rendu de la situation

**Tenants.** La mise à niveau de SecurityCenter 5.14 dépend d'une configuration SQL compatible avec l'initialisation de la base Directory.

**Aboutissants.** Le journal du ticket décrit l'erreur de conversion datetime et le contournement de langue par défaut SQL. Le ticket est résolu après ce contournement, sans décrire d'autre changement de configuration.

**Objectifs du test.** Vérifier, sur un environnement Genetec de test, la mise à niveau et le démarrage de SecurityCenter 5.14, l'absence de l'erreur SQL 242 et la connexion du plugin vidéo ISAP à SecurityCenter.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** La recherche de `#9006`, « SecurityCenter 5.14 » et « SQL 242 » dans les plans ne retourne aucune occurrence. La section « Genetec – SecurityCenter Video Plugin » du plan 03 décrit la connexion à Genetec, la configuration des moniteurs externes et l'affichage des flux, mais pas l'installation ou la migration de SecurityCenter 5.14 ni le réglage du login SQL utilisé comme contournement.

**Comparaison des procédures.** La section Genetec du plan 03 permet de vérifier que le plugin vidéo communique avec SecurityCenter après la configuration. Le présent ticket relève d'une configuration d'environnement et n'introduit pas de comportement applicatif nouveau ; il convient de conserver cette section et de la compléter par les contrôles de prérequis SQL et de démarrage après mise à niveau, sans créer une fiche produit séparée.

**Issue retenue.** Issue B — Adapter l'existant : compléter la section Genetec du plan 03 avec les vérifications de configuration et de démarrage de SecurityCenter 5.14.

## 4. Procédure de test proposée

**Écarts avec la procédure existante.** Conserver les vérifications existantes de connexion Genetec et d'affichage vidéo. Ajouter les contrôles ci-dessous avant ces étapes ; ne pas reprendre ni diffuser les identifiants éventuellement présents dans le plan ou dans l'environnement.

**Préparation de SecurityCenter 5.14**
- Sur un environnement de test réinitialisable, sauvegarder la base Directory puis effectuer la mise à niveau vers SecurityCenter 5.14. Résultat attendu : la sauvegarde est disponible et le processus de mise à niveau se termine sans interruption. (#9006)
- Avant le premier démarrage après migration, vérifier avec l'administrateur SQL que la langue par défaut du login de service utilisé par SecurityCenter est celle requise par la procédure de test ; si le contournement du ticket est nécessaire, appliquer `us_english` uniquement à ce compte de test. Résultat attendu : la configuration du login est vérifiée sans modifier un environnement partagé ou de production. (#9006)
- Démarrer le service Genetec Server et consulter les journaux de mise à niveau et de démarrage. Résultat attendu : la base Directory s'initialise et le journal ne contient pas l'erreur SQL 242 de conversion `varchar` vers `datetime`. (#9006)
- Ouvrir Security Desk et vérifier la connexion à l'instance SecurityCenter mise à niveau. Résultat attendu : l'application se connecte à l'instance et les fonctions de supervision s'ouvrent sans erreur de base. (#9006)
- Exécuter les étapes existantes de la section Genetec pour établir la connexion du plugin vidéo et afficher un flux caméra depuis la WinApp. Résultat attendu : le flux s'affiche dans le moniteur externe prévu et aucune erreur de connexion au plugin n'est enregistrée. (#9006)
- Après le test, restaurer la base Directory ou rétablir la configuration initiale du clone selon la procédure de l'environnement. Résultat attendu : l'environnement est prêt à être réinitialisé et aucun changement de configuration n'est reporté sur un système partagé. (#9006)

### Prérequis et moyens

- Environnement Genetec 5.14 isolé du site client, avec une base Directory sauvegardée.
- Intervention d'un administrateur SQL pour vérifier ou modifier le login de service ; ne jamais consigner de compte ni de mot de passe dans les résultats.
- Plugin SecurityCenter vidéo et WinApp disponibles pour les contrôles existants du plan 03.

## 5. Intégration proposée

Dans le plan 03, compléter la section **« Genetec – SecurityCenter Video Plugin »** avant les étapes de connexion du plugin, avec les vérifications de mise à niveau SecurityCenter 5.14, de configuration SQL et de démarrage de la base Directory.

## Points ouverts

- Le ticket ne confirme pas si `us_english` est un prérequis permanent de SecurityCenter 5.14 ou un contournement propre à l'environnement observé ; le test doit vérifier le démarrage avec la configuration approuvée par l'administrateur avant généralisation.
