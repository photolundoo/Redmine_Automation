## 1. Étude du sujet

Le ticket signale un délai d'environ quatre secondes lors de la connexion à la Main Courante quand le plugin vidéo est arrêté ou non déployé localement. Un commentaire indique que l'absence du plugin n'était pas remarquée immédiatement, puis une alerte s'est affichée. La description suggère de tester les proxies dans des threads pour éviter de bloquer le client. Le ticket est résolu le 17/08/2026, sans précision sur le correctif réalisé.

## 2. Compte rendu de la situation

**Tenants.** Le problème est observé sur un serveur et reproduit sur un poste après arrêt du plugin vidéo. La configuration connexe est référencée par le ticket #8941.

**Aboutissants.** Le ticket est clôturé comme résolu. L'historique ne donne ni le détail de la solution livrée ni un seuil temporel d'acceptation.

**Objectifs du test.** Vérifier que l'absence du plugin vidéo ne bloque pas l'accès à la Main Courante, que l'indisponibilité est signalée et que la navigation reste possible après l'affichage de l'alerte.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** `#8982` : non trouvé dans les plans consultés. La correspondance de la fonction « WebApp - Accès & Ressources » propose le plan 01 WebApp, notamment MC01 — Généraux. Cette fiche couvre l'ouverture de la page et la connexion, mais pas l'arrêt du plugin vidéo. La recherche de « timeout » et « plugin vidéo » ne révèle pas d'étape correspondante dans MC01. MC05 — Onglet Vidéo exige le plugin CCTV lancé et teste les flux ; cette procédure ne couvre pas l'absence du plugin lors de l'accès à la Main Courante.

**Comparaison des procédures.** Le parcours de connexion de MC01 reste pertinent, mais son jeu de données ne prévoit pas de plugin vidéo indisponible ni d'observation de l'alerte. MC05 porte sur un autre contexte, celui de l'affichage de flux avec le plugin actif. Il faut donc compléter MC01 avec un scénario distinct d'indisponibilité.

**Issue retenue.** B — Adapter l'existant : le test reprend la connexion déjà couverte par MC01, avec un prérequis et des résultats observables spécifiques à l'absence du plugin vidéo.

## 4. Procédure de test proposée

**Écarts avec la procédure existante.** Conserver les contrôles de connexion et d'ouverture de la page d'accueil de MC01. Ajouter le scénario suivant avec le plugin vidéo arrêté. Ne pas interpréter un délai chiffré non défini par le ticket.

**Connexion sans plugin vidéo**
- Dans l'environnement de test, arrêter le plugin vidéo puis ouvrir la page de la Main Courante. Résultat attendu : la page de connexion s'affiche et reste utilisable. (#8982)
- Se connecter avec un compte autorisé. Résultat attendu : l'accès à la Main Courante aboutit et l'indisponibilité du plugin vidéo est signalée dans l'interface. (#8982)
- Naviguer vers une fonctionnalité disponible de la Main Courante après le signalement. Résultat attendu : le client reste utilisable et le signalement ne bloque pas la navigation. (#8982)
