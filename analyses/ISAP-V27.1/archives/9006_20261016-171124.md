## 1. Étude du sujet

Le ticket concerne l'installation et la configuration de SecurityCenter 5.14. Après une migration, le démarrage de Genetec échouait pendant la création des entités par défaut, à la suite d'une conversion de date invalide dans la base SQL. Le contournement consigné dans le ticket porte sur la langue par défaut du compte SQL utilisé par le service.

## 2. Compte rendu de la situation

**Tenants.** La migration de SecurityCenter vers la version 5.14 déclenchait une erreur SQL au démarrage de Genetec.

**Aboutissants.** Le ticket indique que le problème a été contourné en configurant la langue par défaut du compte SQL du service comme attendu par Genetec, puis qu'il a été résolu. Il ne décrit pas d'autres modifications du plugin vidéo.

**Objectifs du test.** Vérifier que la base SQL et SecurityCenter 5.14 démarrent après l'installation ou la migration, que l'erreur de conversion de date ne réapparaît pas et que l'intégration vidéo avec la WinApp reste observable.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** La recherche de `#9006` et de « 5.14 » dans les plans ne retourne aucune occurrence. « SecurityCenter » est présent dans le plan 03, dans les sections « Plugin SecurityCenterVideoPlugin » et « Genetec – SecurityCenter Video Plugin ». Cette dernière contient le sous-titre « SDK SecurityCenter - Genetec » et les contrôles de lancement de SecurityDesk et d'affichage du flux depuis la WinApp. Aucun test Playwright existant ne cite ce ticket.

**Comparaison des procédures.** La procédure existante vérifie le démarrage du serveur Genetec, l'accès à Surveillance et l'affichage des flux vidéo sur les moniteurs externes. Elle ne contrôle ni la migration vers 5.14, ni le paramètre SQL lié à l'erreur de conversion de date, ni les journaux du démarrage. Ces vérifications ciblées doivent compléter les contrôles d'intégration existants.

**Issue retenue.** Issue B — Adapter l'existant : la fiche WVID01 couvre déjà l'intégration Genetec et le flux vidéo, mais pas la migration de SecurityCenter 5.14 ni l'erreur SQL décrite.

## 4. Procédure de test proposée

**Écarts avec la procédure existante.** Conserver la vérification de l'ouverture de Surveillance et de l'affichage des flux vidéo dans la section « SDK SecurityCenter - Genetec ». Ajouter les contrôles de la configuration SQL et du démarrage de la version 5.14 avant de rejouer ces étapes d'intégration.

**Installation et migration de SecurityCenter 5.14**
- Avant la migration, vérifier que le compte SQL utilisé par le service Genetec a la langue par défaut requise par l'installation, sans exposer ses identifiants. Résultat attendu : la configuration correspond aux prérequis du service. (#9006)
- Installer ou migrer SecurityCenter vers la version 5.14 dans l'environnement de test. Résultat attendu : l'installation ou la migration se termine sans erreur. (#9006)
- Démarrer les services Genetec puis consulter leurs journaux de démarrage. Résultat attendu : le service Directory termine la création de ses entités par défaut sans erreur de conversion de date ni erreur SQL associée. (#9006)
- Ouvrir SecurityDesk et afficher Surveillance. Résultat attendu : l'application s'ouvre, le serveur reste connecté et aucune erreur de base de données n'apparaît au démarrage. (#9006)
- Depuis la WinApp, afficher un flux vidéo sur un moniteur externe configuré pour Genetec. Résultat attendu : le flux de la caméra est visible et reste disponible après un redémarrage des services. (#9006)

### Prérequis et moyens

- Un serveur de test isolé et réinitialisable, SecurityCenter 5.14 et une base SQL de test.
- Les droits nécessaires pour consulter les paramètres du compte de service SQL et les journaux Genetec ; utiliser `<IDENTIFIANT_COMPTE_SQL>` si un identifiant doit être reporté.
- Une WinApp reliée au serveur Genetec et une caméra de test dont le flux est disponible.

## 5. Intégration proposée

Dans le plan 03, sous la fiche **WVID01 — Module Vidéo WinApp**, ajouter un sous-titre « Installation et migration de SecurityCenter 5.14 » avant « SDK SecurityCenter - Genetec ». Conserver ensuite les contrôles existants d'accès à Surveillance et d'affichage vidéo.
