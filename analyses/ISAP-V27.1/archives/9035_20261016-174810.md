## 1. Étude du sujet

Le ticket demande de créer un tableau de bord listant les capteurs selon leur type et l'état de leurs attributs booléens, puis de choisir les colonnes affichées. Les exemples couvrent les capteurs PAV pleins, les guichets non armés et les pannes. Le ticket précise que les attributs autres qu'Active ne sont pertinents que lorsque Active vaut True.

## 2. Compte rendu de la situation

**Tenants.** Il s'agit d'une évolution de la WebApp, dans le module Tableau de bord de la Main Courante. Un commentaire mentionne un essai de tableau de bord PAV dans un environnement de test ; aucune description textuelle de résultat n'est jointe.

**Aboutissants.** Le ticket est résolu et lié à #9093. Il ne décrit pas de résultat de validation au-delà de la capture d'écran du tableau de bord d'essai.

## 4. Procédure de test proposée

**Créer et filtrer un panneau de capteurs**
- Ouvrir un tableau de bord modifiable et ajouter un panneau d'action configuré pour l'élément « Sensor ». Résultat attendu : le panneau est ajouté au tableau de bord et affiche les capteurs accessibles dans le dossier. (#9035)
- Configurer le filtre de type pour ne conserver que VERRE, EP et OM, puis définir Active = True et Triggered = True. Résultat attendu : seules les lignes des capteurs accessibles qui satisfont ces critères sont affichées ; les capteurs d'autres types ou dont un attribut ne correspond pas sont absents. (#9035)
- Remplacer les critères par le type ARME avec Active = True et Triggered = False. Résultat attendu : seules les lignes correspondant à ces critères sont affichées. (#9035)
- Configurer Active = True et Failure = True sans limiter les types. Résultat attendu : les capteurs en panne correspondant aux critères sont affichés, quel que soit leur type. (#9035)
- Dans la configuration des colonnes, sélectionner DisplayName et Description, puis valider. Résultat attendu : ces colonnes sont affichées et les autres colonnes non sélectionnées sont absentes. (#9035)
