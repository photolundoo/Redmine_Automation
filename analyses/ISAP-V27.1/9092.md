## 1. Étude du sujet

Le ticket demande de permettre à GitHub Copilot de lire directement les tickets Redmine, afin qu'un utilisateur puisse lui demander le détail d'un ticket. La procédure interne de configuration est mentionnée dans l'historique. La résolution du 21/10/2026 indique que le fonctionnement est confirmé avec la dernière version de Visual Studio Insiders.

La capture jointe montre une interaction de Copilot demandant le contenu d'un ticket et faisant appel aux outils MCP Redmine pour consulter la demande et une pièce jointe.

## 2. Compte rendu de la situation

**Tenants.** Le besoin est une lecture des tickets Redmine depuis GitHub Copilot au moyen du MCP Redmine configuré dans Visual Studio Insiders.

**Aboutissants.** Le ticket est résolu après que les MCP personnalisés sont devenus disponibles dans Visual Studio Insiders. Il demande de suivre la procédure interne puis de vérifier que Copilot récupère les détails d'un ticket.

**Objectifs du test.** Confirmer que Copilot peut lire, en accès lecture seule, les informations du ticket demandé et, pour un ticket comportant une pièce jointe, que la pièce jointe peut être consultée par le MCP.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** `#9092`, MCP Redmine et Visual Studio Insiders ne sont pas cités dans les plans. La correspondance de fonction oriente vers les plans 13, 02, 11 et 12. Le plan 13 contient des procédures ISAP API Server et SmartShieldWebAPI ; elles testent l'API ISAP et son outil Explorer, non une intégration MCP dans Visual Studio. Les occurrences de Redmine dans les plans 02 et 13 ne décrivent pas non plus cette intégration.

**Comparaison des procédures.** Aucune procédure existante ne configure le MCP Redmine ni ne vérifie la récupération de tickets par Copilot. Les tests d'API existants empruntent un autre parcours et ne permettent pas de valider ce besoin.

**Issue retenue.** D — Nouvelle procédure manuelle : l'installation et l'utilisation se font dans Visual Studio Insiders et le résultat est une réponse Copilot fondée sur le ticket Redmine consulté.

**Rattachement retenu.** La décision humaine valide la création d'un nouveau plan intitulé « Intégration MCP Redmine », dédié à la validation de cette intégration.

## 4. Procédure de test proposée

**Lecture d'un ticket Redmine par Copilot via MCP**
- Suivre la procédure interne de configuration du MCP Redmine dans Visual Studio Insiders, puis ouvrir une conversation GitHub Copilot. Résultat attendu : le MCP Redmine est disponible dans la session Copilot sans message d'erreur de configuration ou de connexion. (#9092)
- Demander à Copilot de lire un ticket Redmine autorisé pour le compte de test, en précisant son numéro. Résultat attendu : Copilot récupère le ticket demandé et restitue son sujet ainsi que les principaux champs visibles du ticket, sans les confondre avec un autre ticket. (#9092)
- Comparer la réponse de Copilot aux informations visibles dans la page Redmine du ticket de test. Résultat attendu : les champs rapportés correspondent au ticket consulté et les informations non présentes dans le ticket ne sont pas inventées. (#9092)
- Pour un ticket de test comportant une pièce jointe, demander à Copilot de consulter cette pièce jointe. Résultat attendu : le MCP fournit la pièce jointe associée au ticket et Copilot en restitue uniquement les informations effectivement observables. (#9092)
- Vérifier dans Redmine que le test n'a modifié ni le ticket ni sa pièce jointe. Résultat attendu : les données du ticket restent inchangées après les requêtes de lecture. (#9092)

### Prérequis et moyens

- Visual Studio Insiders à une version prenant en charge les MCP personnalisés et GitHub Copilot activé.
- Configuration du MCP Redmine effectuée selon la procédure interne mentionnée dans le ticket.
- Compte de test autorisé à lire un ticket non sensible et ses pièces jointes ; ne pas inscrire d'identifiant ni de mot de passe dans les résultats.
- Ticket de test dont les informations et, le cas échéant, la pièce jointe sont consultables pour le compte utilisé.
- Vérifier les résultats en lecture seule ; ne pas modifier le ticket ni appeler l'API Redmine directement.

## 5. Intégration proposée

Créer le plan **Intégration MCP Redmine** et y intégrer une fiche dédiée portant le même titre, avec les étapes de configuration et de lecture en accès non modifiant des tickets et pièces jointes Redmine.
