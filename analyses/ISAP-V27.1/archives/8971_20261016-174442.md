## 1. Étude du sujet

Le ticket étend le MCP afin de créer un incident à partir de l’entityId de son IncidentType, sans exiger le champ Code. Iris doit récupérer les types d’incident, sélectionner celui qui correspond à son nom ou à son DisplayName, puis transmettre son entityId dans `alarm_type_eid`. Le paramètre `code` reste accepté pour compatibilité, et une erreur est signalée si aucun identifiant ni code valable n’est fourni.

## 2. Compte rendu de la situation

**Tenants.** Certains types d’incident, notamment des types manuels, n’ont pas de Code prédéfini. Le parcours doit donc sélectionner un type à partir de son nom affiché et de son entityId.

**Aboutissants.** La livraison indique que le MCP transmet `alarm_type_eid` au endpoint de création, et qu’Iris sélectionne le type à partir de Name ou DisplayName. Le paramètre Code reste disponible pour les clients existants.

**Objectifs du test.** Vérifier qu’Iris crée un incident pour le type demandé sans dépendre du Code et que le type retenu est celui dont l’entityId a été envoyé.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** La recherche de `#8971`, « alarm_type_eid », « entityId » et « IncidentType » dans les plans ne retourne aucune étape. Le plan 13 contient une section SmartShieldWebAPI consacrée à la connexion à l’API et à des opérations d’alarme, mais pas au parcours Iris/MCP décrit ici. La fiche WIN15 de ce plan concerne les drones et ne correspond pas à ce besoin.

**Issue retenue.** Issue D — Nouvelle procédure manuelle : le flux de sélection du type par Iris et de transmission de l’entityId au MCP n’est pas couvert par les procédures actuelles.

## 4. Procédure de test proposée

**Création d’un incident par entityId**
- Dans l’environnement de test, choisir un IncidentType possédant un entityId et ne possédant pas de Code exploitable. Résultat attendu : le type est disponible dans la liste des IncidentType et ses attributs Name ou DisplayName permettent de le reconnaître. (#8971)
- Demander à Iris de créer un incident correspondant à ce type. Résultat attendu : Iris sélectionne le type demandé et le MCP transmet son entityId dans `alarm_type_eid`. (#8971)
- Rechercher l’incident dans la Main Courante. Résultat attendu : l’incident est créé et son type correspond à l’IncidentType choisi. (#8971)
- Vérifier les traces de l’appel MCP si elles sont disponibles dans l’environnement. Résultat attendu : l’appel de création contient `alarm_type_eid` correspondant au type choisi et ne dépend pas d’un champ Code. (#8971)

### Prérequis et moyens

- Un environnement Iris/MCP de test avec un IncidentType de test identifiable par Name ou DisplayName et sans Code exploitable.
- Un compte de test autorisé à créer des incidents et à consulter la Main Courante.
- Accès aux traces d’appel MCP dans l’environnement de test, si ces traces sont disponibles.

## 5. Intégration proposée

Créer dans le plan 13 Outils externes la fiche **À créer — Iris — Création d’incident par entityId**, séparée de la section SmartShieldWebAPI existante, puis la soumettre à relecture humaine selon la correspondance des fonctions.
