## 1. Étude du sujet

La WebAPI permet désormais de créer un incident à partir de l’entityid de son IncidentType, sans dépendre du champ Code qui n’est pas systématiquement renseigné.

## 2. Compte rendu de la situation

**Tenants.** Certains types d’incident ne possèdent pas de Code utilisable par l’API.

**Aboutissants.** L’API accepte l’identifiant d’entité du type d’incident.

**Objectifs du test.** Vérifier la création avec entityid, y compris pour un type sans Code.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** La recherche de #8970 dans le plan 13 ne retourne aucune étape. La fiche **SmartShieldWebAPI** couvre les parcours API sans ce paramètre.

La procédure complète cette fiche.

## 4. Procédure de test proposée

**Création API par entityid**
- Appeler l’API de création avec l’entityid d’un IncidentType dépourvu de Code. Résultat attendu : la réponse confirme la création de l’incident. (#8970)
- Ouvrir Main Courante et rechercher l’incident créé. Résultat attendu : l’incident porte le type demandé. (#8970)

## 5. Intégration proposée

Ajouter ces étapes à **SmartShieldWebAPI** du plan 13 Outils externes.
