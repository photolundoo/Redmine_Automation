## 1. Étude du sujet

Le ticket regroupe des anomalies rencontrées lors de déploiements Ansible sur des machines Linux : des templates de configuration WebApp devenaient obsolètes, le contrôle de configuration écrasait le fichier existant, les liens symboliques de bibliothèques étaient incorrects et certains changements de permissions ou de paquets étaient manquants. Les mises à jour ont remplacé l'usage de templates complets par des remplacements ciblés, supprimé le script qui écrasait la configuration et corrigé les dépendances et liens. Le ticket indique toutefois qu'il restait à vérifier que les ajouts et modifications de clés dans `maincourante.config.js` fonctionnent.

## 2. Compte rendu de la situation

**Tenants.** Les déploiements Ansible installaient et mettaient à jour ISAP sur des serveurs Linux ; des écarts apparaissaient entre les fichiers de configuration présents sur le serveur et les versions d'exemple du dépôt.

**Aboutissants.** L'historique décrit des corrections sur les liens symboliques, les permissions du certificat, la configuration par expressions régulières, les dépendances Python et les droits des répertoires. Le ticket est résolu après ces modifications.

**Objectifs du test.** Rejouer une installation ou une mise à jour Ansible sur un clone Linux, vérifier que seuls les paramètres attendus sont remplacés, que les fichiers existants ne sont pas écrasés sans raison et que les dépendances et liens créés sont utilisables.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** La recherche de `#9001`, « Ansible », « maincourante.config.example.js » et « check_maincourante.py » dans les plans 11 Installation client sur PC et 12 Update version ne retourne aucune procédure de déploiement Ansible. UPD02 « Monter de version » décrit une mise à jour avec les installateurs Windows et un contrôle du fingerprint ; il ne couvre pas les scripts d'installation Linux, les variables d'inventaire ni la préservation ciblée de la configuration. La recherche dans le plan 13 Outils externes ne retourne pas non plus de procédure Ansible.

**Issue retenue.** Issue D — Nouvelle procédure manuelle, car les vérifications nécessitent une machine Linux, Ansible, des fichiers système et la consultation des journaux, hors du navigateur.

## 4. Procédure de test proposée

**Installation et mise à jour Ansible**
- Restaurer un clone Debian de test avec une configuration WebApp déjà personnalisée, puis relever les valeurs des clés qui ne doivent pas changer. Résultat attendu : l'état initial est connu et les paramètres personnalisés sont préservés pour la comparaison. (#9001)
- Lancer le playbook Ansible sur le clone avec un inventaire de test. Résultat attendu : l'exécution se termine sans erreur et les dépendances Python requises par le déploiement sont installées. (#9001)
- Comparer `maincourante.config.js` avec sa sauvegarde initiale et le fichier d'exemple de la version déployée. Résultat attendu : seules les clés d'hôte et d'accès prévues par l'inventaire sont remplacées par expressions régulières ; les autres paramètres personnalisés restent présents et aucun fichier complet n'est écrasé par un contrôle de configuration. (#9001)
- Vérifier les liens symboliques créés dans les répertoires de bibliothèques vidéo et TIL. Résultat attendu : chaque lien pointe vers une bibliothèque existante, aucun lien ne conserve un motif générique non développé et les composants dépendants peuvent charger leurs bibliothèques. (#9001)
- Vérifier les permissions du certificat et des répertoires ISAP après le déploiement. Résultat attendu : les permissions attendues sont appliquées sans changement répétitif anormal et le service peut lire les fichiers nécessaires. (#9001)
- Redémarrer les services ISAP, puis consulter leurs journaux et la configuration effective. Résultat attendu : les services démarrent sans erreur de fichier de licence ni de dépendance ; les valeurs personnalisées de `maincourante.config.js` sont conservées après redémarrage. (#9001)

### Prérequis et moyens

- Un clone Debian réinitialisable et un inventaire Ansible de test ; ne pas exécuter les essais sur un site client.
- Les fichiers de configuration et de licence de test doivent être fournis par l'administrateur ; aucune valeur sensible ne doit être recopiée dans le compte rendu.
- Un accès en lecture aux journaux de déploiement et aux liens symboliques produits.
