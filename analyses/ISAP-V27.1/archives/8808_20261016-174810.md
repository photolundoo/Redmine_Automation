## 1. Étude du sujet

Le ticket demande l'envoi automatique de messages liés aux incidents et aux PoliceLogs, filtré par type et adressé soit à l'agent pris en charge, soit à une liste d'agents associée à une SecurityCompany prédéfinie. Il demande aussi la saisie dans la Main Courante des messages reçus des agents, pièces jointes comprises. L'historique décrit le service webhook, le plugin dans la grille et des essais sur téléphone ; un commentaire du 16/07/2026 indique que le test a été validé et accepte le regroupement dans une même mention des messages envoyés pendant une minute, les messages envoyés à des minutes distinctes produisant des mentions distinctes.

## 2. Compte rendu de la situation

**Tenants.** Le parcours traverse la Main Courante, le plugin WhatsApp et un service webhook. Le ticket signale des contraintes de compte Business, de modèles de messages approuvés, de consentement et de configuration de production ; aucune valeur de secret ni donnée personnelle n'est reprise ici.

**Aboutissants.** Le plugin a été livré sur une grille et un test sur téléphone est déclaré validé. Le ticket indique également que la documentation a été ajoutée au plan 13. La rubrique « Plugin WhatsApp » de ce plan ne contient toutefois pas d'identifiant de fiche ni de procédure.

**Objectifs du test.** Vérifier le filtrage des messages sortants vers les destinataires configurés, puis la réception d'un message et d'une pièce jointe d'un agent dans la Main Courante. Confirmer le regroupement temporel décrit dans le test validé.

## 3. Comparaison avec l'existant

**Issue retenue.** C — Créer une procédure : le plan 13 contient une rubrique dédiée, mais aucune procédure à adapter ; les fonctionnalités du ticket nécessitent des étapes explicites d'intégration et de validation.

## 4. Procédure de test proposée

**Vérifier l'envoi automatique depuis la Main Courante**
- Avec une configuration de test dont le modèle est approuvé, créer un incident d'un type filtré et attribuer sa prise en charge à l'agent de test. Résultat attendu : un message est reçu sur le compte de test de cet agent. (#8808)
- Créer un incident d'un type non filtré par la configuration de test. Résultat attendu : aucun message relatif à cet incident n'est reçu par les destinataires testés. (#8808)
- Créer un PoliceLog correspondant à un type filtré et à une SecurityCompany configurée. Résultat attendu : les messages sont reçus par les agents prévus pour cette SecurityCompany, sans envoi à un destinataire hors de la liste configurée. (#8808)

**Vérifier la réception des messages et pièces jointes**
- Depuis le téléphone de test, répondre au message reçu et joindre un fichier de test. Résultat attendu : le message entrant et sa pièce jointe sont accessibles depuis la Main Courante selon le parcours livré. (#8808)
- Envoyer deux messages pendant la même minute, puis un autre au cours d'une minute distincte. Résultat attendu : les deux premiers sont regroupés dans le commentaire d'une mention et le message ultérieur crée une mention distincte, conformément au test validé. (#8808)
