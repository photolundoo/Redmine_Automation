## 1. Étude du sujet

Le ticket étend le MCP pour créer un incident à partir de l’entityId de l’IncidentType, sans exiger le champ Code. Iris récupère les types, les identifie par Name ou DisplayName et transmet l’entityId dans `alarm_type_eid`. Le champ Code reste accepté pour compatibilité ; le ticket indique qu’une erreur est levée si aucun paramètre valide n’est fourni.

## 2. Compte rendu de la situation

**Tenants.** Certains types d’incident, notamment des types manuels, n’ont pas de Code prédéfini. La sélection doit donc pouvoir s’appuyer sur le nom affiché et l’entityId.

**Aboutissants.** La livraison décrite transmet `alarm_type_eid` au endpoint de création et permet à Iris de choisir le type à partir de Name ou DisplayName.

**Objectifs du test.** Vérifier qu’Iris crée un incident du type demandé par entityId sans dépendre d’un Code renseigné.

## 3. Comparaison avec l'existant

**Recherche dans les plans.** La recherche de `#8971`, « alarm_type_eid », « entityId » et « IncidentType » ne trouve aucune étape dédiée. La section SmartShieldWebAPI du plan 13 couvre des opérations API, mais pas le parcours Iris/MCP décrit dans le ticket ; WIN15 traite des drones et est hors sujet.

**Issue retenue.** Issue D — Nouvelle procédure manuelle : la sélection du type par Iris et la transmission de son entityId ne sont couvertes par aucune procédure existante.

## 4. Procédure de test proposée

**Création d’un incident par entityId**
- Dans l’environnement de test, choisir un IncidentType doté d’un entityId et sans Code exploitable. Résultat attendu : Name ou DisplayName permet de reconnaître le type dans la liste des IncidentType. (#8971)
- Demander à Iris de créer un incident correspondant à ce type. Résultat attendu : Iris sélectionne le type demandé et le MCP transmet son entityId dans `alarm_type_eid`. (#8971)
- Rechercher l’incident dans la Main Courante. Résultat attendu : l’incident est créé et son type correspond à l’IncidentType sélectionné. (#8971)

### Prérequis et moyens

- Environnement Iris/MCP de test avec un IncidentType de test identifiable par Name ou DisplayName et sans Code exploitable.
- Compte de test autorisé à créer des incidents et à consulter la Main Courante.
- Accès aux traces d’appel MCP si elles sont disponibles dans l’environnement.
